# Adobe Connect Local Web UI

این پوشه یک رابط وب لوکال برای `adobe_connect_downloader9.py` است. ظاهر UI در این نسخه مینیمال، سفید و بر پایه رنگ #4f72c8 طراحی شده است:

- دریافت لینک کلاس فقط برای ساخت لینک دانلود ZIP، بدون ورود برنامه به session
- آپلود فایل ZIP ضبط بعد از دانلود دستی
- انتخاب فقط چهار کیفیت خروجی: 360p، 480p، 720p و 1080p
- پیشنهاد پیش‌فرض 480p برای رندر قابل‌قبول روی اکثر لپ‌تاپ‌ها
- هشدار داخل برنامه که 720p و 1080p به سیستم قوی‌تر نیاز دارند و زمان رندرشان طولانی‌تر است
- گزینه‌ی «گرافیک NVIDIA GTX 1050 یا بالاتر دارم» برای رندر سریع‌تر با GPU/NVENC
- انتخاب المان‌های داخل ویدیو: PDF/اسلاید، Screen Share، Chat، Pointer، Annotation و صدا
- ورود مستقیم به صفحه پلیر بعد از شروع پردازش
- نمایش وضعیت ساخت و لاگ زنده
- فعال شدن خودکار پلیر بعد از آماده شدن MP4
- کنترل سرعت پخش از 1 تا 4 برابر


## روند جدید دانلود و ساخت کلاس

در این نسخه دانلود کلاس داخل برنامه و با session انجام نمی‌شود. روند پیشنهادی این است:

1. لینک کلاس/recording را وارد کن.
2. برنامه لینک دانلود ZIP را می‌سازد.
3. بعد از دانلود کامل فایل ZIP، آن را در UI آپلود کن.
4. کیفیت، المان‌ها و گزینه‌های خروجی را انتخاب کن و همان‌جا رندر را شروع کن.


## کیفیت‌های فعال

کیفیت‌های خیلی بالا و اضافی حذف شده‌اند و فقط این چهار حالت در UI نمایش داده می‌شود:

| کیفیت | کاربرد |
| --- | --- |
| 360p | سبک‌ترین حالت برای سیستم‌های ضعیف |
| 480p | حالت پیشنهادی برای اکثر لپ‌تاپ‌ها |
| 720p | کیفیت بهتر، ولی کندتر و نیازمند سیستم قوی‌تر |
| 1080p | سنگین و زمان‌بر؛ مناسب سیستم قوی |

## حالت پیشنهادی 480p

برای سیستم‌های ضعیف یا متوسط، گزینه‌ی **480p / پیشنهادی** بهترین انتخاب پیش‌فرض است. این حالت برای کاهش فشار CPU و سریع‌تر شدن رندر این تنظیمات را اعمال می‌کند:

- خروجی 854x480
- رندر صحنه با 1fps
- screen-share با 6fps
- x264 preset روی `ultrafast`
- CRF برابر 31 برای حجم و فشار کمتر
- صدای 96k
- به‌روزرسانی پیش‌نمایش زنده با فاصله بیشتر تا خودش باعث کندی نشود

علاوه بر این، رندر PDFها متناسب با رزولوشن خروجی انجام می‌شود؛ بنابراین صفحه‌های PDF با اندازه‌ی خیلی بزرگ ساخته و بعد کوچک نمی‌شوند.

## رندر با GPU برای NVIDIA GTX 1050 به بالا

در صفحه تنظیمات یک گزینه ساده برای GPU وجود دارد:

**گرافیک NVIDIA GTX 1050 یا بالاتر دارم**

اگر این گزینه فعال شود، برنامه encoder را روی `h264_nvenc` می‌گذارد تا در سیستم‌های پشتیبانی‌شده رندر ویدیو با GPU سریع‌تر انجام شود. اگر `ffmpeg`، درایور NVIDIA یا خود کارت گرافیک از NVENC پشتیبانی نکند، برنامه قبل از رندر اصلی تست کوتاه انجام می‌دهد و در صورت خطا به CPU/libx264 برمی‌گردد.

## پیشنهاد برای سریع‌ترین خروجی

اگر سیستم خیلی ضعیف است، در کنار انتخاب 480p یا 360p می‌توانی در بخش «المان‌های داخل ویدیو» مواردی مثل **Chat**، **Pointer** و **Annotation** را خاموش کنی. اگر screen-share لازم نیست، خاموش کردن **Screen Share** بیشترین اثر را روی سرعت دارد.

## اجرا

### ویندوز
روی فایل زیر دوبار کلیک کن:

```bat
run_ui.bat
```

### لینوکس / مک

```bash
chmod +x run_ui.sh
./run_ui.sh
```

بعد مرورگر را باز کن:

```text
http://127.0.0.1:5000
```

## پیش‌نیاز مهم

برنامه اصلی برای ساخت ویدیو به `ffmpeg` و `ffprobe` نیاز دارد. باید هر دو در PATH سیستم باشند.

## نکته درباره مشاهده همزمان

بعد از زدن دکمه شروع، فوراً وارد صفحه پلیر می‌شوی و پیشرفت ساخت را زنده می‌بینی. فایل MP4 وقتی mux نهایی کامل شود داخل پلیر فعال می‌شود، چون MP4 معمولی تا قبل از پایان کامل، در مرورگر قابل پخش پایدار نیست.

## فایل‌های مهم

- `app.py`: سرور Flask و APIهای UI
- `web_runner.py`: wrapper برای اجرای رندر و فیلتر کردن المان‌ها
- `templates/`: صفحات HTML
- `static/`: CSS و JavaScript
- `outputs/`: خروجی‌های MP4
- `uploads/`: ZIPهای آپلودشده
- `jobs/`: فایل‌های موقت هر پردازش

## رفع مشکل Unicode در ویندوز

در این نسخه `run_ui.bat` و پردازش داخلی برنامه خروجی Python را با UTF-8 اجرا می‌کنند تا لاگ‌های فارسی و علامت‌هایی مثل `▶` روی ویندوز باعث خطای `UnicodeEncodeError` نشوند.

## پیش‌نمایش زنده هنگام رندر

در این نسخه، صفحه پلیر لازم نیست تا پایان کامل MP4 فقط لودر نشان بدهد. وقتی مرحله رندر فریم‌ها شروع شود، آخرین فریم ساخته‌شده در همان صفحه به‌صورت زنده نمایش داده می‌شود و بعد از آماده شدن خروجی نهایی، پلیر MP4 خودکار جایگزین پیش‌نمایش می‌شود.

نکته: این پیش‌نمایش برای سبک و سریع ماندن، تصویری است و صدای نهایی بعد از آماده شدن MP4 داخل پلیر پخش می‌شود.

## پخش بخش‌های ۱۰ دقیقه‌ای هنگام رندر

در این نسخه، خروجی دیگر فقط بعد از پایان کامل رندر در پلیر ظاهر نمی‌شود. برنامه ویدیو را به بخش‌های حدوداً ۱۰ دقیقه‌ای تبدیل می‌کند:

1. هر بخش بعد از رندر شدن با صدای همان بازه به MP4 مستقل mux می‌شود.
2. همان بخش فوراً در صفحه پلیر ظاهر می‌شود و قابل پخش است.
3. بخش‌های بعدی به لیست پلیر اضافه می‌شوند و پلیر می‌تواند بعد از پایان یک بخش، بخش بعدی آماده را پخش کند.
4. بعد از آماده شدن همه بخش‌ها، برنامه آن‌ها را به یک MP4 کامل می‌چسباند و دکمه دانلود/پخش نسخه کامل فعال می‌شود.

مقدار پیش‌فرض هر بخش در وب‌اپ ۶۰۰ ثانیه، یعنی ۱۰ دقیقه است. برای اجرای مستقیم از خط فرمان هم می‌توان از گزینه زیر استفاده کرد:

```bash
python adobe_connect_downloader9.py --zip recording.zip -o class.mp4 --segment-seconds 600 --size 854x480 --fps 1 --screen-fps 6
```

## اصلاح نمایش Screen Share در مرز بخش‌های ۱۰ دقیقه‌ای

در این نسخه یک مشکل مهم در حالت رندر بخش‌بخش رفع شده است: اگر یک فایل `screenshare_*.flv` از مرز یک بخش ۱۰ دقیقه‌ای رد می‌شد، ممکن بود یکی از بخش‌ها اسکرین‌شیر را خالی/سیاه نشان بدهد. علت این بود که بریدن مستقیم FLV با `ffmpeg -ss` روی بعضی ضبط‌های Adobe Connect، مخصوصاً streamهای screen-share کم‌فریم یا timestampدار، قابل اعتماد نیست.

اکنون قبل از overlay، برای هر بخش ۱۰ دقیقه‌ای یک clip جداگانه از screen-share ساخته می‌شود:

- FLV اسکرین‌شیر با فیلتر `trim` دقیقاً به بازه‌ی همان بخش بریده می‌شود.
- قبل از `trim`، فیلتر `fps` اعمال می‌شود تا اگر بخش جدید وسط دو آپدیت screen-share شروع شد، آخرین فریم معتبر نگه داشته شود و ابتدای بخش سیاه نشود.
- timestampها با `setpts=PTS-STARTPTS` صفر می‌شوند تا overlay هر پارت دقیقاً از زمان درست خودش شروع شود.

فایل‌های موقت این برش‌ها داخل مسیر job، در پوشه‌ی `screenshare_segment_clips` ساخته می‌شوند.

```
adobe_connect_web_ui/static/fonts/
```

فایل `static/style.css` از قبل برای وزن های مختلف فونت تنظیم شده است.
