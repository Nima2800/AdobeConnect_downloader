# Adobe Connect Local Web UI

یک رابط وب لوکال، ساده و سریع برای دانلود و تبدیل فایل‌های ضبط‌شده Adobe Connect به ویدیوی MP4.

این پروژه یک رابط کاربری مینیمال برای اسکریپت `adobe_connect_downloader9.py` فراهم می‌کند و با طراحی سفید، فونت فارسی و رنگ اصلی `#4f72c8` ساخته شده است.

با استفاده از این رابط می‌توانید لینک دانلود ZIP ضبط کلاس را بسازید، فایل ZIP را به‌صورت دستی دانلود و آپلود کنید، بخش‌های موردنظر ویدیو را انتخاب کرده و روند ساخت خروجی را به‌صورت زنده مشاهده کنید.

---

## ✨ امکانات اصلی

* ساخت لینک مستقیم دانلود ZIP از روی لینک کلاس یا Recording
* بدون ورود برنامه به Session کلاس
* آپلود فایل ZIP بعد از دانلود دستی
* پشتیبانی از کیفیت‌های `360p`، `480p`، `720p` و `1080p`
* انتخاب پیش‌فرض و پیشنهادی `480p`
* امکان استفاده از شتاب‌دهی سخت‌افزاری NVIDIA NVENC
* تست خودکار NVENC و بازگشت به CPU در صورت ناسازگاری
* انتخاب اجزای قابل نمایش در خروجی
* نمایش زنده وضعیت پردازش و لاگ‌ها
* پیش‌نمایش آخرین فریم ساخته‌شده هنگام رندر
* پخش بخش‌های آماده‌شده قبل از پایان کامل پردازش
* اتصال خودکار بخش‌ها و ساخت فایل MP4 نهایی
* کنترل سرعت پخش از `1x` تا `4x`
* پشتیبانی کامل از متن و لاگ فارسی در ویندوز
* رابط کاربری فارسی با فونت Kalameh Fanum

## 🚀 روند دانلود و ساخت کلاس

در این نسخه، دانلود فایل ضبط‌شده داخل برنامه و با Session انجام نمی‌شود.

روند پیشنهادی به این شکل است:

1. لینک کلاس یا Recording را وارد کنید.
2. برنامه لینک مستقیم دانلود ZIP را ایجاد می‌کند.
3. فایل ZIP را به‌صورت دستی دانلود کنید.
4. بعد از کامل شدن دانلود، فایل ZIP را در رابط وب آپلود کنید.
5. کیفیت، المان‌های ویدیو و تنظیمات پردازش را انتخاب کنید.
6. پردازش را شروع کرده و مستقیماً وارد صفحه پلیر شوید.
7. پیشرفت ساخت، پیش‌نمایش فریم‌ها و بخش‌های آماده‌شده را به‌صورت زنده مشاهده کنید.

## 🎬 اجزای قابل انتخاب در ویدیو

هنگام ساخت خروجی می‌توانید مشخص کنید کدام بخش‌های جلسه در ویدیوی نهایی نمایش داده شوند:

* PDF و اسلایدها
* Screen Share
* Chat
* Pointer
* Annotation
* صدا

برای افزایش سرعت پردازش روی سیستم‌های ضعیف‌تر، می‌توانید اجزای غیرضروری مانند Chat، Pointer و Annotation را غیرفعال کنید.

غیرفعال کردن Screen Share، در صورتی که به آن نیاز نداشته باشید، بیشترین تأثیر را روی سرعت رندر خواهد داشت.

---

## 📺 کیفیت‌های خروجی

کیفیت‌های بسیار سنگین و اضافی حذف شده‌اند و فقط چهار گزینه کاربردی در رابط نمایش داده می‌شود:

| کیفیت   | کاربرد                                    |
| ------- | ----------------------------------------- |
| `360p`  | سبک‌ترین حالت برای سیستم‌های ضعیف         |
| `480p`  | گزینه پیشنهادی برای اکثر لپ‌تاپ‌ها        |
| `720p`  | کیفیت بهتر با پردازش سنگین‌تر             |
| `1080p` | مناسب سیستم‌های قدرتمند و رندرهای باکیفیت |

> کیفیت‌های `720p` و `1080p` به پردازنده و سخت‌افزار قوی‌تری نیاز دارند و زمان پردازش آن‌ها بیشتر است.

---

## ⭐ حالت پیشنهادی 480p

گزینه `480p` برای اکثر لپ‌تاپ‌ها و سیستم‌های ضعیف یا متوسط، بهترین انتخاب پیش‌فرض است.

این حالت با هدف کاهش فشار پردازنده و افزایش سرعت رندر از تنظیمات زیر استفاده می‌کند:

* رزولوشن خروجی: `854x480`
* نرخ رندر صحنه: `1fps`
* نرخ Screen Share: `6fps`
* انکودر CPU: `libx264`
* تنظیم x264 preset: `ultrafast`
* مقدار CRF: `31`
* بیت‌ریت صدا: `96k`
* فاصله بیشتر بین به‌روزرسانی‌های پیش‌نمایش زنده

رندر صفحات PDF نیز متناسب با رزولوشن خروجی انجام می‌شود. در نتیجه، صفحات ابتدا با ابعاد بسیار بزرگ ساخته و سپس کوچک نمی‌شوند و فشار غیرضروری روی حافظه و CPU کاهش پیدا می‌کند.

---

## ⚡ شتاب‌دهی با NVIDIA NVENC

در صفحه تنظیمات، گزینه زیر برای فعال‌سازی پردازش با GPU وجود دارد:

> گرافیک NVIDIA GTX 1050 یا بالاتر دارم

با فعال‌کردن این گزینه، برنامه از انکودر `h264_nvenc` استفاده می‌کند تا عملیات ساخت ویدیو روی کارت گرافیک انجام شود.

پیش از شروع رندر اصلی، یک تست کوتاه NVENC اجرا می‌شود. اگر یکی از موارد زیر پشتیبانی نشود، برنامه به‌صورت خودکار به `libx264` و پردازش CPU بازمی‌گردد:

* کارت گرافیک
* درایور NVIDIA
* نسخه FFmpeg
* انکودر NVENC

بنابراین فعال‌کردن این گزینه باعث متوقف شدن پردازش روی سیستم‌های ناسازگار نخواهد شد.

## 🖥️ صفحه پلیر و نمایش زنده پردازش

بعد از فشردن دکمه شروع، کاربر مستقیماً وارد صفحه پلیر می‌شود.

در این صفحه می‌توانید موارد زیر را به‌صورت زنده مشاهده کنید:

* وضعیت فعلی پردازش
* درصد پیشرفت
* لاگ‌های اجرای برنامه
* آخرین فریم ساخته‌شده
* بخش‌های ویدیویی آماده‌شده
* فایل MP4 نهایی پس از تکمیل

تا زمانی که MP4 نهایی آماده نشده باشد، آخرین فریم رندرشده به‌عنوان پیش‌نمایش تصویری نمایش داده می‌شود.

این پیش‌نمایش برای سبک باقی ماندن رابط، بدون صدا است. صدای کامل بعد از آماده شدن بخش‌های MP4 یا فایل نهایی در پلیر قابل پخش خواهد بود.

## 🧩 پخش بخش‌های ۱۰ دقیقه‌ای هنگام رندر

برای اینکه کاربر مجبور نباشد تا پایان کامل پردازش منتظر بماند، خروجی به بخش‌های تقریباً ۱۰ دقیقه‌ای تقسیم می‌شود.

روند ساخت هر بخش:

1. فریم‌های مربوط به بازه زمانی بخش رندر می‌شوند.
2. صدای همان بازه با ویدیو Mux می‌شود.
3. یک فایل MP4 مستقل برای بخش ساخته می‌شود.
4. بخش آماده‌شده بلافاصله در پلیر ظاهر می‌شود.
5. بعد از پایان یک بخش، پلیر می‌تواند بخش آماده بعدی را پخش کند.
6. پس از تکمیل تمام بخش‌ها، آن‌ها به یک MP4 کامل متصل می‌شوند.

مقدار پیش‌فرض طول هر بخش در وب‌اپ برابر با `600` ثانیه، یعنی ۱۰ دقیقه است.

نمونه اجرای مستقیم از خط فرمان:

```bash
python adobe_connect_downloader9.py \
  --zip recording.zip \
  -o class.mp4 \
  --segment-seconds 600 \
  --size 854x480 \
  --fps 1 \
  --screen-fps 6
```

## 🛠️ اصلاح Screen Share در مرز بخش‌ها

در حالت رندر بخش‌بخش، ممکن بود یک فایل `screenshare_*.flv` از مرز یک بخش ۱۰ دقیقه‌ای عبور کند و ابتدای بخش بعدی به‌صورت سیاه یا خالی نمایش داده شود.

این مشکل بیشتر در Streamهای کم‌فریم یا فایل‌های دارای Timestamp خاص دیده می‌شد، زیرا برش مستقیم FLV با گزینه `-ss` در FFmpeg همیشه قابل اعتماد نبود.

در نسخه جدید، پیش از Overlay شدن Screen Share، برای هر بخش یک Clip مستقل ساخته می‌شود:

* فیلتر `fps` پیش از برش اعمال می‌شود.
* آخرین فریم معتبر در شروع بخش جدید حفظ می‌شود.
* فیلتر `trim` بازه زمانی دقیق بخش را جدا می‌کند.
* فیلتر `setpts=PTS-STARTPTS` زمان‌بندی Clip را از صفر آغاز می‌کند.
* Overlay هر بخش دقیقاً در زمان صحیح خود قرار می‌گیرد.

فایل‌های موقت این مرحله در مسیر زیر داخل پوشه Job ساخته می‌شوند:

```text
screenshare_segment_clips/
```

## 📦 پیش‌نیازها

برای ساخت ویدیو، وجود ابزارهای زیر ضروری است:

* Python
* FFmpeg
* FFprobe

دستورهای `ffmpeg` و `ffprobe` باید در PATH سیستم قابل دسترسی باشند.

برای بررسی نصب بودن FFmpeg می‌توانید از دستور زیر استفاده کنید:

```bash
ffmpeg -version
```

و برای FFprobe:

```bash
ffprobe -version
```

## ▶️ اجرا در ویندوز

روی فایل زیر دوبار کلیک کنید:

```bat
run_ui.bat
```

بعد از اجرای سرور، آدرس زیر را در مرورگر باز کنید:

```text
http://127.0.0.1:5000
```

## 🐧 اجرا در لینوکس و macOS

ابتدا فایل اجرا را قابل اجرا کنید:

```bash
chmod +x run_ui.sh
```

سپس برنامه را اجرا کنید:

```bash
./run_ui.sh
```

در نهایت، آدرس زیر را در مرورگر باز کنید:

```text
http://127.0.0.1:5000
```

adobe_connect_web_ui/static/fonts/

## 🪟 پشتیبانی از Unicode در ویندوز

در فایل `run_ui.bat` و پردازش‌های داخلی برنامه، خروجی Python با Encoding نوع UTF-8 اجرا می‌شود.

این تنظیم از بروز خطاهایی مانند مورد زیر جلوگیری می‌کند:

```text
UnicodeEncodeError
```

در نتیجه، لاگ‌های فارسی و کاراکترهایی مانند `▶` در ویندوز بدون مشکل نمایش داده می‌شوند.

## ⚠️ نکته درباره MP4 نهایی

فایل‌های MP4 معمولی تا پیش از تکمیل مرحله Mux نهایی، همیشه به‌صورت پایدار در مرورگر قابل پخش نیستند.

به همین دلیل، برنامه هنگام پردازش از دو روش استفاده می‌کند:

* نمایش آخرین فریم رندرشده به‌عنوان پیش‌نمایش زنده
* ساخت MP4های مستقل برای بخش‌های ۱۰ دقیقه‌ای

بعد از تکمیل تمام بخش‌ها، فایل MP4 نهایی ساخته شده و گزینه پخش و دانلود نسخه کامل فعال می‌شود.
